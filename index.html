TethrLink turns a tablet into a second display you can touch.

An Android tablet becomes a genuine second monitor for Linux over a USB cable — no Wi-Fi, no router, no cloud. Not a mirror: GNOME arranges it like any other display, and windows you drag onto it stay there. Version 2.0.0 adds touch, so your finger drives the pointer.

What 2.0.0 added

Tap to click, drag to drag, long-press to right-click, two-finger drag to scroll. Gesture timings come from Android's own ViewConfiguration, so they match every other app on the tablet and honour its accessibility settings.

Touch is off by default. Something that can drive your desktop should be opted into, so you turn it on in the server window — and the platform, not our care, keeps it honest: input goes through GNOME's RemoteDesktop API, which scopes it to the virtual display. It cannot reach your laptop's own screen.

The hard part

The tether subnet can't be assumed. An earlier version hardcoded 192.168.42.0/24 — the AOSP default — and broke on every device that hands out something else. What is actually reliable is which interface is USB-attached: on Linux, /sys/class/net/<iface>/device resolves through a path segment named usbN for USB-enumerated devices and never for PCI or bridges. So the server enumerates those interfaces, reads whatever subnet each currently has, and serves only those peers plus loopback.

Install

Snap is the short path — one command, no build.

$ sudo snap install tethrlink

Requires GNOME on Wayland for the virtual display and touch. X11 falls back to JPEG, video only — and the app says so rather than pretending otherwise.

Layer-7 load balancer

Go · TypeScript control plane · Apr – Jun 2025
HTTP request→Go net/http LB→ RR / WRR / LeastConn→health check→backend pool

A Layer-7 balancer in Go with Round Robin, Weighted Round Robin and Least Connections, plus a TypeScript control plane for changing weights and circuit-breaker settings while traffic is flowing.

The hard part

Getting the circuit breaker to fail usefully. Ejecting an unhealthy backend immediately just moves its load onto the next one and takes that down too, so the breaker needs a cooldown window before a backend is eligible again — otherwise a single slow service cascades through the whole pool.

RetrieveX — hybrid search engine

BM25 + dense retrieval over 150k+ drug records
Source
query→BM25 · Elasticsearch+BERT · FAISS →reciprocal rank fusion→Django REST · P95 <200ms

Lexical and dense retrieval run side by side and are merged with reciprocal rank fusion, behind a Django REST API. Three plug-and-play backends — Lucene, Elasticsearch, and BERT/FAISS — so the retrieval strategy is swappable rather than baked in.

The hard part

Lexical and semantic scores aren't on a comparable scale, so blending them by score means tuning a weight that only holds for the queries you tuned it on. Fusing by rank instead sidesteps the calibration problem entirely and keeps both backends independently replaceable.

Fluid–structure interaction framework

M.S. thesis · FEniCSx · PETSc · MPI
Source
Navier–Stokes (ALE)⇄nonlinear solid →Dirichlet–Neumann + Aitken→ALE mesh motion →<0.5% vs Turek–Hron

A modular pipeline coupling an ALE Navier–Stokes fluid solver, nonlinear solid mechanics and mesh motion, validated across 9 benchmarks (CFD1–3, CSM1–3, FSI1–3) over six refinement levels, with configuration-driven runs and checkpoint restart.

The hard part

Partitioned FSI diverges when the fluid and structure have comparable density — the added-mass effect. Fixed-point iteration simply won't converge. Aitken relaxation adapts the step from the residual history each iteration, which is what makes the FSI2 oscillation stable rather than explosive.

Research

Physics where the data runs out.

Battery degradation data is expensive to collect and sparse at exactly the conditions you care about. A model that only knows the data extrapolates badly there; one that also knows the governing equations does not.

Journal of Power Sources · Vol. 627, 2025 · IF ~8.1

Hybrid PDE–ML model for Li-ion degradation

Physics-informed PDEs combined with Gaussian Process Regression over 200k+ charge cycles, forecasting State of Charge, State of Health and Remaining Useful Life for NCA cells across varying temperature and C-rate — with GPR, Random Forest, SVM, XGBoost and neural networks compared as an ensemble.

The hard part

Making the physics actually constrain the fit rather than sit alongside it. The PDE terms have to enter where the data is thinnest — otherwise the ML half simply overrides them and you have a data-only model wearing a physics label.

Validation, not vibes

The framework is checked against the Turek–Hron benchmarks that everyone in the field reports — the same quantities, the same meshes, published numbers to disagree with.
